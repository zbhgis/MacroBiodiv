## 实际部署流程（2026-10-03 走通版）

前提：本机已配置对 `root@47.98.133.104` 的 SSH 免密登录；DNS A 记录已生效
（`nslookup macrobiodiv.zbhgis.com` → 47.98.133.104）。

### ① 先装「仅 80 端口」的引导配置（鸡生蛋问题：签证书前 443 证书还不存在）

仓库内已留档：`deploy/nginx-macrobiodiv.bootstrap.conf`（只含 acme 验证 location）。

```bash
scp deploy/nginx-macrobiodiv.bootstrap.conf root@47.98.133.104:/etc/nginx/conf.d/macrobiodiv.conf
ssh root@47.98.133.104 "nginx -t && nginx -s reload"
```

> ⚠ 踩坑：手册初版假设主站 nginx 的 :80 兜底会服务 `/opt/mystation/frontend`
> 里的验证文件 —— 实测 404，Let's Encrypt 的 order 会卡死在
> 「CA is processing / retryafter=86400」。必须先有上面的引导块。

### ② 清掉卡死的旧订单（仅首次卡住时需要），签发证书

```bash
ssh root@47.98.133.104 "rm -rf ~/.acme.sh/macrobiodiv.zbhgis.com_ecc"
ssh root@47.98.133.104 "~/.acme.sh/acme.sh --issue -d macrobiodiv.zbhgis.com \
  --webroot /var/www/acme/macrobiodiv --keylength ec-256"
```

> webroot 与引导配置里的 `root /var/www/acme/macrobiodiv` 一致
> （初版手册写的 /opt/mystation/frontend 是错的）。
> 可先验证：往 `/var/www/acme/macrobiodiv/.well-known/acme-challenge/` 放测试文件，
> `curl http://macrobiodiv.zbhgis.com/.well-known/acme-challenge/<文件名>` 能取回即通。

### ③ 安装证书（续期时自动 reload）

```bash
scp deploy/_install_cert.sh root@47.98.133.104:/tmp/   # 仓库内已留档
ssh root@47.98.133.104 "bash /tmp/install_cert.sh; rm -f /tmp/install_cert.sh"
```

> 走脚本文件是为了避开 PowerShell/ssh 双层引号吞掉 `--reloadcmd "nginx -s reload"`
> 的内层引号（会报 Unknown parameter: -s）。

### ④ 换上完整 Nginx 配置（80 跳转 + 443 静态站 + /api/ 反代统计）

```bash
scp deploy/nginx-macrobiodiv.conf root@47.98.133.104:/etc/nginx/conf.d/macrobiodiv.conf
ssh root@47.98.133.104 "nginx -t && nginx -s reload"
```

### ⑤ 站点文件上服务器

```bash
scp -r site/. root@47.98.133.104:/var/www/macrobiodiv/
```

> 手工 scp **不删除**服务器上已下线的旧文献目录（会累积失效页）；日常发布走
> 管理界面「发布」（同步前清空 webroot 再全量上传，并自动做搜索引擎推送）。

日常：管理界面点「发布」（勾选"同步到服务器"）自动完成，无需手动。

### ⑥ 封面图片本地化（本仓库 images/，2026-10-05 起；已并入发布任务自动执行）

卡片与详情页引用**本仓库**的图片（GeoSciPlot images/ 同款存储）：
`images/full/{id}.{ext}`（原图）+ `images/thumb/{id}.webp`（缩略图），
经 jsDelivr 分发（`cdn.jsdelivr.net/gh/zbhgis/MacroBiodiv@main/images/...`）。
nginx 与服务器**不承载任何图片流量**——images/ 不随 `site/` 部署，随 git 仓库走。

**发布任务已自动处理**：管理后台点「发布」时，流水线第一步会增量本地化新封面
（下载原图入 `images/` → 压缩缩略图 → cover/cover_thumb 改写为本仓库链接），
失败不阻断发布（卡片回退原图外链，下次发布自动重试）；images/ 随发布的
`git add -A` 一起提交推送，jsDelivr 对新路径即时生效。

手动运行仅作应急/全量重建：

```bash
python scripts/prepare_thumbs.py            # 增量；--force 全量重做
```

- 增量运行：只处理 `cover` 尚未指向本仓库的文献；缩略图优先复用旧图床克隆
  `E:/AAAproject/BlogImg/blog/thumb/`（历史备份，仅作复用源）
- 前提：Pillow（`pip install pillow`，仅此工具需要；站点构建/管理后台零依赖）
- ⚠ 同路径重传封面受 jsDelivr 缓存影响可能滞后 12h+ 才更新
- 忘跑这步不会坏（发布任务本来就会自动跑）：卡片回退原图外链（每张 2MB 级，
  只是慢），补跑后下次发布生效
